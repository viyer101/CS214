chatd.c --> The project implements a multi-client chat server using TCP sockets and the poll() system call. The server supports the following message types:
    1) NAM - this sets the user screen name
    2) SET - this updates the user status
    3) MSG - this sends public/private messages 
    4) WHO - queries user or room information
    5) ERR - outputs error responses 
The chat server was tested across four main categories - that being 1) Core Functionality Tests, 2) Protocol Correctness Tests, 3) Edge Case and boundary tests, 4) Last Field | Tests, and 5) Multi-Client interaction tests. Testing was performed primarily using - printf '...' | nc localhost <port>, which avoids newline issues presented by the interactive nc.
1) Core Functionality Tests: Login (NAM) -> tested using command through bash printf '1|NAM|4|Bob|' | nc localhost 5555, which gives a welcome message. We tested also using a duplicate name as well with command through bash printf '1|NAM|4|Bob|1|NAM|4|Bob|' | nc localhost 5555, which gives us an expected error (ERR 1). Status update (SET) -> we first checked normal status using command through bash printf '1|NAM|4|Bob|1|SET|17||Smiling Politely|' nc localhost 5555, which broadcasts the message to all users in the server. We then tested empty status using command through bash printf '1|NAM|4|Bob|1|SET|1||' | nc localhost 5555, which accepts the message but does not broadcast it.
2) Protocol Correctness Tests: Fatal Errors (ERR 0) -> we used command through bash printf '2|NAM|4|Bob|' | nc localhost 5555 which uses the wrong protocol version. We then used the command through bash terminal printf '1|ABC|4|Bob|' | nc localhost 5555 which tests invalid message type. We then tested non-numeric length using the command through bash terminal printf '1|NAM|xx|Bob|' | nc localhost 5555, which gives an error (ERR 0) and closes the connection to the chat server.
3) Edge Case and Validation boundary Tests: Name Validation -> we tested illegal characters using this command through the bash terminal printf '1|NAM|4|Bo!|' | nc localhost 5555, which gives an error (ERR 3). We then tested long strings passed using the command printf '1|NAM|34|ABCDEFGHIJKLMNOPQRSTUVWXYZABCDEFG|' | nc localhost 5555, which also gives an error (ERR 4). Status Validation, Message Validation, WHO Query Validation and Recipient Validation are all tested through using long strings passed using the command '1|NAM|4|Bob|1|MSG|38|ABCDEFGHIJKLMNOPQRSTUVWXYZABCDEFG|Hi|' | nc localhost 5555 which gives an error (ERR 4). We also tested Recipient Validation by using an illegal recipient with the command printf '1|NAM|4|Bob|1|MSG|10|Al!ce|Hi|' | nc localhost 5555 which gives an error (ERR 3). We also tested recipient validation through testing for an unknown valid recipient by printing through the bash terminal printf '1|NAM|4|Bob|1|MSG|10|Alice|Hi|' | nc localhost 5555, which gives an error (ERR 2). We tested similar cases  such as illegal name and unknown valid user for WHO Query Validation tests which gave the same error type like before (ERR 3 and ERR 2 respectively).
4) Last Field | Tests: Status with | -> we tested this case through executing the command printf '1|NAM|6|Carol|1|SET|9|hi|there|' | nc localhost 5555, which the server accepts. Message with | -> we tested this case through executing the command printf '1|NAM|4|Eve|1|MSG|11|#all|a|b|c|' | nc localhost 5555, which the server also reads as acceptable.
5) Multi Client Interaction Tests: Broadcast messaging -> Two clients are connected and one sends printf '1|MSG|20|#all|Hello, world!|' | nc localhost 5555, and all users in the server receive the message. Regarding private messaging, it's between two clients and one sends a message to the other and we tested this through command printf '1|NAM|4|Bob|1|MSG|32||Alice|Private message to Alice|' | nc localhost 5555, and only Alice receives the message. We also tested the WHO Room Query through executing command printf '1|NAM|4|Bob|1|WHO|5|#all|' | nc localhost 5555, which returns all connected users.
6) Recoverable Error Test: The errors (1-4) don't terminate the connection to the chat server, so we run the command print '1|NAM|4|Bob|1|MSG|10||Alice|Hi|1|MSG|16||#all|Recovered|' | nc localhost 5555. In the first attempt, message would give an error (ERR 2) without terminating the connection, but the second attempt would succeed in terminating the connection to the server.
7) We also tested with the sample client tar file given to us (clients.tar). We ran ./chatd 5555 through the first terminal, then opened a new client terminal and ran ./client Alice localhost 5555, which printed "Welcome to the chat!" in Alice's terminal. Then in Bob's terminal we ran ./client Bob localhost 5555 and it printed the same message. We then ran the command /Smiling Privately through Bob's server, testing status broadcast and it prints Bob is smiling privately on both Bob and Alice's terminals, respectively. We also tested private messaging by printing @Alice Private Hello, which Bob sends and Bob sees- To Alice: Private Hello, and Alice sees - From Bob: Private Hello.

The server passes all core functionality tests, protocol validation tests, all edge case and boundary validation tests, and multi-client interaction tests as well.
